## Callable boundary

`src/main/kotlin/com/bettercontent/tests/suite/drivers/CaseDrivers.kt` exposes `DriverRegistry.resolve(id)`, `requireSupported(ids)`, `ordered(cases, requested)`, `CaseDriver.plan(parameters: JsonNode): List<DriverStep>` and `evaluateCase(driver, parameters, terminalObservations): DriverOutcome`. A step includes its native action ID, strictly typed JSON parameters, timeout ticks and a strict `source` (`server` by default, or `client` for separately authored client-side drivers). Session orchestration must route each request to its own authenticated native mailbox, match full envelope run/case/token/request sequence and native terminal kind, and collect terminal payloads from exactly the planned source; server observations cannot stand in for client evidence. Unsupported case or dependency, malformed/failing native action, missing/extra/reordered terminal, lost server, failed native cleanup, or missing evidence is **fatal/inconclusive**, never a passing case. A valid complete native observation that contradicts an independently authored expected value is a **failed** case, not a fatal transport error. `fixture.cleanup` belongs in the session's unconditional `finally`; its owned-residual count must be zero, including on failed cases. The driver library does not create fixtures, start worlds, log in players or substitute its own fake players.

### Before a real campaign

Review the protocol in `docs/playtest-protocol-v2.md`, bind the exact native test-support artifact and candidate pair, acquire a strict target manifest from installed item/block registries and real recipe/loot/acquisition mapping, verify real-player connection and normal use completion semantics, and supply authored expectations. Add new drivers only with bounded native actions, independent before/after assertions and negative/boundary tests; do not alias dozens of catalogue IDs to generic snapshot or interaction success. All execution still requires explicit human permission.

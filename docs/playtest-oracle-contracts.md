## Exact distribution, precommitted before outcomes

`src/main/kotlin/com/bettercontent/tests/suite/oracles/ExactDistributionOracle.kt` accepts SHA-bound JSON `bc.playtest_distribution_plan.v1` and `bc.playtest_distribution_samples.v1` (schemas in `src/test/resources/playtest/schemas/`). Reviewer must fix **before the first outcome**: exact candidate **and one immutable family ID** (the external qualifier must refuse any second/replacement plan for that candidate+family), exact independent eligible sampling frame and its SHA, unique selected unit IDs and **N=1..512**, mutually exclusive exhaustive bin labels, fixed hypotheses for individual bins, bounded rational null rates and explicit sampler semantics (`ideal-independent-bernoulli-v1` or `uniform-nextfloat-lt-v1` only), **predetermined directional alternatives**, and nonzero per-hypothesis family alpha allocations summing to **at most 10,000 parts per million = 1%**. The review/provenance of the eligible units and their claimed independence is outside this pure statistical function. Do not choose seed/sites/bins, adjust alternatives, stop early, replace failed sites, discard ambiguous results or retry after seeing outcomes. The result is a conditional exact integer binomial tail for each predeclared alternative; no normal approximation or adaptive confidence interval. Bonferroni controls whole-family false rejection *conditional on valid independent Bernoulli units/null rates*. For `uniform-nextfloat-lt-v1`, the independently bound provider must show its exact binary Float threshold and an actual uniform 24-bit `nextFloat() < threshold` decision: the oracle's exact grid-count adapter yields denominator 16,777,216 (e.g. `0.8f` differs from ideal 4/5). `<=`, `nextDouble`, compound/randomized provider calls and unreviewed threshold semantics are NOT supported by that label. Correlated sites or unknown population make the statistical interpretation inconclusive even if code computes a number. A null-compatible result is **not evidence that an unobserved category exists**; a rejection is narrow evidence against the declared null in the predeclared direction, not gameplay or whole distribution qualification.

**Producer→consumer contract requested from A/B/C:** (1) A pre-binds the approved plan SHA, review time and exact candidate *outside all epoch-writable mounts* before any eligible site is observed. (2) An independent world/native producer records each preselected site ID, natural origin and no-replacement/independence basis, exact available tag/biome/food category, classification rule and actual sample time; plan's `sampling_frame_sha256` is only an eligible-list digest, **not** proof of natural terrain or independence. (3) A separately verifies raw native/site observations, producer PID/birth/epoch, capture clock and complete one-to-one unit IDs and serializes them into `bc.playtest_distribution_samples.v1`; missing, wrong, ambiguous, off-plan or duplicate samples are inconclusive. (4) The oracle reads those SHA-bound bytes only after external raw replay; it cannot authenticate self-reported times, silently classify invalid samples or prove an absent category by compatibility alone. Registered food roster and worldgen outputs are **not** retrospectively samples until such a producer exists.

## Only known vanilla Damage transitions

`VanillaDurabilityOracle.kt` consumes A's existing `checkpoints.NbtValue`/`NbtList` representation, with recursively exact byte/int/long-array comparisons, rather than a second parser or an opaque SNBT/hash comparison. It accepts **only** a predeclared vanilla `minecraft:` one-count tool, independently observed known max damage, unenchanted/no modifiers, explicit typed `tag.Damage` integer and a separately observed break-callback Boolean. A non-break result matches only the exact expected +1 Damage and *all other typed NBT unchanged*, including nested lists, raw float bits, id, Count and Slot. The original `evaluate` break branch matches only when pre-damage is max−1, an independent break callback is observed and the observed after stack is absent; do not pass a later source-refilled saved slot to that branch. Missing cap, absent/malformed typed Damage, enchantment/Unbreakable/ForgeCaps/ForgeData, unknown callback or unreviewed modifier state is **inconclusive**. A contradicting complete observation is `failed`, never a probabilistic durability assumption. In the legacy `evaluate` signature, `after=null` is **only a proven observed empty slot**; a missing or unverified capture must be withheld from that function. For an expected non-break, complete observed EMPTY, a wrong saved item, or loss of the required typed tag/Damage is `failed`, not an absent-evidence downgrade. This is not tool acquisition, actual loot/pickup, a generalized mod-tool capability oracle, or saved-world persistence proof.

**Producer→consumer contract requested from A/B:** reuse the existing *verified* checkpoint `SealedPlayerInventory` typed-NBT reader and its canonical stack identity for saved before/after when applicable; if native output is used, emit exact typed stack bytes with actor UUID, slot, source callback/tick and verified matching canonical stack digest. A should expose one **bounded typed stack value** from its existing parser/verified snapshot (or bind B's native typed codec) rather than making D copy the NBT parser or treating a hash as reversible bytes. Independently bind actual vanilla item registry max damage, absence of enchantment modifiers/opaque capabilities and exact event-owned break callback; a fake-player action without these facts stays inconclusive. No A/B files were changed by D.

For count1 it requires exactly one balanced cause, the actual destroy-return **runtime** EMPTY of the original object, the exact bound source UUID and live selected-slot EMPTY→entire acquired source Count/item/canonical/content identity with all other forty slots unchanged, source terminal absence, and a separately saved final slot whose typed ID/Count agree with the *same-captured* sealed hash/Count and actual source. The runtime EMPTY is **not** an intermediate sealed checkpoint and the final source item (e.g. cobblestone) is **not** a mutated iron tool. This narrow verdict is not world continuity, final transformed bytecode or a live test result; source+regressions unrun pending A serialized compile-only checks and a separately approved future runtime.

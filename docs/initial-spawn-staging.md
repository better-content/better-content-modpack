# Initial shared-spawn staging and recovery (generation zero only)

**Not a release or a friends' playtest result.** Earlier terrain-gated fixtures and the subsequent ten passing pre-blacklist full-pack trials do not validate the current ocean-blacklist revision. Fresh worlds require the final saved biome and the two blocks immediately above it to remain within Cold Sweat's configured habitable base-temperature bounds **and outside `#minecraft:is_ocean`** (including warm and deep frozen oceans); vanilla can place a first-join spectator a block above the saved shared spawn. `config/better_world_management-initial-spawn-blacklist.txt` may exclude additional registered biome IDs; missing or empty files cannot permit ocean spawns. This is initial-world policy only; terrain safety is not gated because new players scout in spectator mode. Source edits do not update an installed mod JAR.

## Fresh dedicated world

Launch through `./run.sh`, never directly through Forge. With generation zero, an absent `level-name` save is prepared under `.better_world_management/initial-spawn/<run>/universe-<attempt>/bc-initial-<id>`; only loopback network listeners are configured. The raw `level-seed` server-property value is captured before rewriting temporary properties. Empty input permits distinct random-seed attempts; nonempty or unavailable input never permits seed rotation. The candidate persists `level.dat` without a server-tick flush of all chunks; normal shutdown must flush the closed save. Only then are its saved spawn/seed and V3 parametric receipt (at the existing `initial-spawn-attempt-v2.tsv` path) checked before atomic no-replace promotion. The supervisor restores the *original bytes* of `server.properties` and reopens the final world. All rejected candidates stay protected under the run directory.

A fresh server without the companion staged mod refuses preparation: **do not replace it with a direct Forge launch**. When a world already exists, the regular world launch and successor transaction remain separate from this flow.

## Fresh single-player world

The normal Create World screen retains its generation display. Candidate saves live outside `saves/` under `.better_world_management/initial-spawn/<transaction>/staging/`. The client waits without making a local connection, checks a verified receipt against the saved `level.dat`, stops the integrated server, moves the closed candidate into `saves/` without replacing an existing name, and only then reloads it. Failed attempts are retained under the transaction directory. An explicit seed with no eligible non-blacklisted biome fails closed; there is no unchecked vanilla fallback.

## Interrupted or failed preparation

- A failed or interrupted candidate is **not** a playable world. Never move an attempt folder into the final world name merely because `initial-spawn-v1.tsv` says `pending` or `resolved`.
- A dedicated `active-v2.tsv` marker blocks the next launch. Inspect the protected transaction and any player data/login marker first; check whether the final world name already exists. The run directory holds `server.properties.before` with the original bytes. If an abrupt kill interrupted restoration, restore those bytes before deliberately resolving the marker. Do **not** delete an established or inhabited world to retry.
- In single-player, the protected `staging/` and `attempt-N/` folders are retained for inspection; never open one as a normal save. A world already in `saves/` is not rotated or reselected.
- Protected `attempt-N-supervisor-v2.tsv` (dedicated) and `creation-intent-v2.tsv` (single-player) preserve original seed provenance even when startup fails before world creation. Raw seed input is base64-encoded there; encoding is **not encryption**. `initial-spawn-attempt-v2.tsv` is a restricted file: new V3 receipts include the seed, provenance, target, status, final spawn coordinates, biome ID, registered base temperature and loaded temperature bounds; historical V2 receipts are still readable for established worlds. The old `initial-spawn-v1.tsv` retains the status string for existing pack readers. A failed attempt has a separate `initial-spawn-outcome-v2.tsv` with a bounded reason; `kind=retry` permits another **random-seed** attempt only, while technical failures and deadlines do not.

No automatic recovery operation deletes or overwrites a published save. Review protected receipts and restore backups before any manual cleanup. To roll back the feature, restore the previous mod and supervisor/client-hook artifacts through the normal release process; **never roll back, delete, or regenerate a published player world**. Owner/unit/native tests require separate human approval to run; packaging, deployment, and publication use their own gates.

## Independent client boundary

The Forge client observer is in `test-support/forge/src/main/java/com/bettercontent/playtestsupport/client/`; it loads only on `Dist.CLIENT` and requires three dedicated JVM properties: `bc.playtest.client.directory`, `bc.playtest.client.runId`, and `bc.playtest.client.token`. Its precreated fresh mailbox, token, request ordinal and `source:"client"` observations are **distinct** from the server mailbox. Missing/linked directories, unplanned actions, stale IDs, failed callbacks and missing client connection fail closed. The coordinator must attach a bound `client_stream` to each relevant v3 epoch and provide independently reviewed per-case client action plans before any GUI/EMI assertion can qualify. The presence of this code or a claimed `passed` state is not proof that the client loaded it.

Implemented source-only action IDs: `client.snapshot` (real joined client screen/menu slots, full player inventory NBT as SNBT plus its digest, position/dimension), `client.framebuffer` (Minecraft framebuffer PNG written directly, never generated from a mock image), `client.emi_index` (pinned EMI 1.1.24 **public** `EmiApi.getIndexStacks` and `EmiApi.getRecipeManager().getRecipes()` with source-JAR SHA check), `client.input_key` (actual `KeyboardHandler.keyPress` press/release for an unmodified inventory-open E when no screen is visible or allowlisted navigation keys on a visible screen), and `client.input_click` (actual `Screen.mouseClicked`/`mouseReleased` callbacks with bounded visible GUI coordinates). Input requests and returned client UI state have an append-only client `input-events.jsonl`; the raw request/observation transport retains the existing v2 envelope but cannot be relabeled v3 campaign evidence. Read-only `verifyV3ClientEvidence` rejects swapped/replayed callbacks and server-origin assertions, hashes the PNG and EMI export, decodes PNG pixels, and checks the exact reviewed action roster. The server's native action descriptor remains separate.

## Narrow authored cases (not the broad GUI/EMI promises)

`client.emi.public-index` (`client.emi.index-roster`) uses the actual joined client public-API export and compares its complete sorted index-ID and recipe ID/category/output **multisets** with separately authored expected rosters. Duplicate IDs are retained because distinct EMI stacks may share an ID; this does not prove NBT-variant identity. Export bytes are bounded, captured once, hash-checked and parsed with duplicate-key/trailing-document rejection. Anonymous recipes or unsupported public outputs currently block export rather than being omitted. This does **not** assert tags, recipe ingredients/catalysts, usage lookups, GUI navigation or visible recipe approval; historical `client.emi.promise` remains unsupported. `client.inventory.sync` (`client.inventory.slot-sync`) compares actual server and client before/after occupied slots and selected hotbar slot around an explicit, behavior-only owned `fixture.begin` item grant and bounded server wait.

## Exact native acquisition evidence

The exact-hash PNCR 6.0.22 artifact contains static Amadron recipes for `assembly_program_drill`, `assembly_program_laser`, `assembly_program_drill_laser`, and `pcb_blueprint`. The three program purchases are removed. The native Blueprint offer is replaced with a static barter of four pressure tubes for one Blueprint, alongside its separate 1.5-bar pressure recipe; other fluid/emerald Amadron services remain. The native Drill+Laser combination recipe remains. Laser Program and the first PCB Blueprint pressure recipe have no printed-PCB or instrumentation input. The native unassembled-PCB recipe requires the Laser Program, while native Assembly Laser requires a printed PCB; the pressure Blueprint recipe and tube-barter alternative provide source-level first-Blueprint routes without a printed-PCB prerequisite. Actual first-board reachability still requires candidate verification.

Inspection of the pinned `VillagerTradesRegistration` bytecode found mechanic offers for PCB Blueprint, printed PCB, and the base Drone. Script 82 filters those outputs. The native base Drone route in script 81 is gated at 5 bar. A scan of all 155 PneumaticCraft loot tables found two direct progression bypasses in `pneumaticcraft:chests/mechanic_house.json`: `pneumaticcraft:amadron_tablet` (weight 2), and `pneumaticcraft:advanced_pressure_tube` (weight 4). Script 82 removes both exact outputs from that table. Advanced tube loot filtering remains in place, but does not protect the current plant recipe, which uses ordinary pressure tube. Other component loot is retained. A historical scan of the retained installed server JAR set found no other matching direct service or advancement acquisition in loot tables, and no other-mod recipe creating a targeted PneumaticCraft capability/service item. That bounded static scan is not a current cross-mod acquisition census; current pack recipe overrides also include progression/82 and /85 as linked above. Compressed Creativity adds `data/compressedcreativity/loot_tables/blocks/bracketed_advanced_pressure_tube.json`, and PneumaticCraft has `data/pneumaticcraft/loot_tables/blocks/advanced_pressure_tube.json`; both are block-break recovery for already-placed advanced tubes, not a new origin for obtaining the first tube. These source changes are covered by the focused unit contract, but their KubeJS/MoreJS/LootJS registration has not been loaded in a candidate.

The pinned native Empty PCB pressure-chamber recipe does not consume the PCB Blueprint; that Blueprint crafts the native UV Light Box. Its authored recipe has no PCB or instrumentation input. Actual UV exposure producing the first printed PCB and complete acquisition reachability remain acceptance work.

## Source closure still required

This inventory is the source manifest required by TECH-03, but it does not close TECH-03 or TECH-07. Remaining source work is to reconcile cross-mod trader and world-generation acquisition sources, trace the complete prerequisite graph for native services and outputs, and close any bypasses of authored local-economy or meteor gates without removing required native behavior. Source removes the three Amadron program purchases, replaces the Blueprint purchase with pressure-tube barter, retains separate pressure crafting, filters the listed villager sales, and removes mechanic-house Tablet/advanced-tube loot. These are scoped acquisition policies, not proof of a complete graph or an advanced-tube gate on the plant. KubeJS registration, the actual earliest route graph, thermal/pressure safety, UV first-board behavior and all remaining acquisition closure require candidate-matched evidence; historical unit checks do not establish that acceptance.
